# BKK Markov passenger-flow model — TDK 2026

Corvinus TDK 2025/26 submission: *A Multi-Modal Markov-Chain Passenger-Flow
Model for the BKK Budapest GTFS Network* (Marcell Molnár), together with the
code that produces every number in the paper.

## Data

BKK GTFS Schedule feed, CC0-1.0, <https://opendata.bkk.hu>. The paper uses the
June 2026 release. Place the archive at `data/budapest_gtfs.zip`
(or run `python scripts/tdk_rerun.py --download`).

## Reproducing the paper

Windows:

```powershell
.\futtatas.ps1        # install, run everything, build paper.pdf
```

Step by step:

```bash
pip install -e ".[all]"
python scripts/tdk_rerun.py --zip data/budapest_gtfs.zip   # also runs paper_dynamics.py and paper_tables.py
cd paper && ./forditas.sh
```

`tdk_rerun.py` calls `paper_dynamics.py` and `paper_tables.py` automatically,
so the tables always match the run. The whole pipeline takes about 30–40
minutes on a laptop, mostly the bus node-removal sweep, plus about 35 minutes
for `paper_augment.py` (mostly the tram layer). All random streams are
seeded.

## Main results (June 2026 feed)

- Network: 5 177 stops, 6 450 scheduled links; tram, metro, bus, ferry.
- KFE conserves passengers to 1e-15; exact SSA on the metro agrees with the
  KFE mean within 0.84 %, τ-leaping on the full network within 2.4 %.
- The spectral gap is zero on every modal chain (metro periodic, tram/bus
  reducible), so criticality uses Kemeny's constant and network efficiency.
- Metro criticality: Deák Ferenc tér (1.00), Kálvin tér (0.62),
  Keleti pályaudvar (0.44); removing Deák cuts metro efficiency by 49 %.
- Augmentation: three metro links bypassing Deák/Kálvin (Rákóczi tér–Arany
  János utca, Fővám tér–Opera, Fővám tér–Vörösmarty tér) cut the worst-case
  loss from 44.5 % to 18.8 % (J −52 %); the M5 inner section gives −28 %;
  greedy is within 5 % of exhaustive search for B = 2.

## Known scope limits

- Trolleybus and HÉV are coded as `route_type` 11 and 109 in the current feed;
  `bkk/constants.py` expects 800 and 2, so they are not in the analysed network.
- `C_i` in the paper is computed in `scripts/paper_tables.py` from the
  components defined for each chain; `bkk/resilience.py` still stores the
  three-component average in its `criticality` column.
